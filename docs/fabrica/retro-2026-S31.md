# Retrospectiva S31 - Cryptic Trainer PWA

## 1. Qué se shipeó
- **Catálogo de Equipos (v1.2.0):** Integración de `equipment.json` para definir cabinas físicas (Ej: J, W, Y) por equipo (A350, A320).
- **Escaleras de Clases Dinámicas:** Filtrado en `ResponseGenerator` y validación robusta en `PnrStateMachine` para comandos de disponibilidad (SN, AN) y reserva (SS).
- **Restauración E2E:** Bypass de la pantalla de login inyectando un token en `localStorage` desde los test de Playwright, destrabando la suite completa.

## 2. Patrones y problemas
- **Regresión silenciosa en testing:** Al introducir el `LoginScreen` (v1.1.0), los test E2E quedaron bloqueados. Esto demostró que el flujo de QA previo no falló de inmediato o fue omitido, revelando una desconexión entre el desarrollo de UI y el mantenimiento de tests automatizados.
- **Código de test filtrándose a producción:** La solución actual inyecta lógica de E2E directamente en `App.jsx` (`if (localStorage.getItem('PLAYWRIGHT_TEST'))`). Esto ensucia la base de código.

## 3. Proceso
- El ciclo funcionó bien al final (la ejecución disciplinada de `/qa` desenmascaró el timeout de 60s en Playwright). Sin embargo, el fallo se originó al saltarnos la ejecución estricta de Playwright justo después de fusionar la autenticación de Firebase en el sprint pasado.

## 4. Mejora accionable
**Implementar Auth Mocking real en Playwright**
- **Descripción:** Eliminar el bypass de `localStorage` en `App.jsx` y reemplazarlo con un mock de la API de Firebase a nivel de red (usando `page.route` o fixtures de Playwright) para aislar completamente el código de producción.
- **Dueño:** Ingeniería
- **Para cuándo:** Siguiente Sprint.
